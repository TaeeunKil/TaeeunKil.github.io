# 하루 한 강, CMU 컴퓨터과학 공부노트

2026-11-17 사용자와 정한 공부 연재 계획이다. 이 블로그 저장소에서 CMU 공개 강의를 공부하고, 하루 한 편을 목표로 공부노트와 글 초안을 쌓아 간다. 현재는 연재 계획을 기록한 단계이며, 1편 작성이나 공개 게시를 완료한 상태는 아니다.

## 연재 방향

- 강좌 하나를 정해 강의 순서대로 공부한 뒤 다음 강좌로 넘어간다.
- 첫 강좌는 **17-214 Principles of Software Construction(소프트웨어 구축 원리)**로 시작할 계획이다. 실제 학습을 시작할 때 공개 여부와 강의 순서를 확인한다.
- 하루에 정리할 수 있는 분량을 한 편으로 삼는다. 긴 강의는 여러 편으로 나눠도 된다.
- 편 번호는 연재 전체에서 1편, 2편, 3편으로 이어 간다. 강좌가 바뀌어도 번호를 유지하고 각 글에 강좌명을 표시한다.
- 날짜보다 학습 순서를 기준으로 이어 간다. 쉬는 날이 있어도 다음 편 번호부터 계속한다.

## 글 제목과 목차

연재 이름은 **하루 한 강, CMU 컴퓨터과학 공부노트**로 한다. 개별 글 제목은 다음 형식을 사용한다.

> CMU 공부노트 1편 — [오늘 배운 핵심 주제]

2편, 3편도 같은 형식으로 늘린다. 편별 주제는 실제 강의와 학습 내용을 확인한 뒤 정한다. 계획만으로 강의 내용을 추정해 제목이나 본문을 채우지 않는다.

이 문서를 연재의 시작점으로 사용하고, 글을 작성할 때 아래 목차에 링크와 진행 상태를 추가한다.

| 편 | 주제 | 상태 | 글 |
| --- | --- | --- | --- |
| 1편 | 첫 강의 확인 후 결정 | 시작 전 | — |

## 매 편에 담을 내용

1. **오늘의 질문**: 이번에 무엇을 이해하려는지 적는다.
2. **개념 설명**: 필요한 배경부터 자신의 말로 풀어 쓴다.
3. **작은 예제나 실습**: 개념이 어떻게 쓰이는지 확인한다. 실행하지 않은 예시는 실습 결과로 쓰지 않는다.
4. **헷갈린 점**: 아직 이해하지 못한 부분과 추가 확인이 필요한 내용을 남긴다.
5. **다음에 확인할 것**: 다음 학습으로 이어질 질문을 적는다.
6. **출처**: 강좌명, 영상 링크, 다룬 시간 구간과 참고 자료를 기록한다.

강의에서 설명한 내용, 추가 자료로 보완한 내용, 직접 실습해 확인한 내용을 구분한다. 실제로 수강하거나 실행하지 않은 내용을 학습 경험으로 서술하지 않는다.

## 시각 자료와 글 검수

- 구조, 처리 흐름, 비교, 수치를 그림으로 설명하면 이해가 쉬워지는 지점을 먼저 찾는다. 필요한 경우 다이어그램, 그래프, 캡처 등을 넣고 장식용 그림은 억지로 추가하지 않는다.
- 설명용 가정과 실제 측정 결과를 구분하고, 단위와 범위, 생략한 요소, 필요한 출처를 캡션에 적는다.
- 블로그의 `DESIGN.md`에 있는 색과 서체를 따르고 모바일과 PC에서 잘림과 글자 크기를 확인한다.
- 조작 가능한 그림은 키보드 동작과 JavaScript 없이 읽을 수 있는 기본 상태를 확인한다.
- 초안은 기존 `writing/` 작업 방식에 맞춰 준비하고, 공개 게시 상태는 별도로 기록한다.

## 다음 작업의 시작점

1. CMU 공식 강좌 목록에서 17-214의 실제 영상과 연결된 강의 자료를 찾는다.
2. 첫 영상의 제목, 링크, 길이와 내용을 확인해 하루 학습 분량을 정한다.
3. 해당 분량을 공부하며 출처와 질문, 예제 또는 실습 근거를 모은다.
4. **CMU 공부노트 1편** 초안을 작성하고 이 문서의 목차를 갱신한다.

이 문서는 공부 연재 계획이다. 매일 자동 실행하거나 자동 게시하는 일정은 설정하지 않았다.
