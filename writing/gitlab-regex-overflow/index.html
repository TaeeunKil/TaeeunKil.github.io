GitLab 정규식 오버플로가 인증 없는 RCE로 이어진 과정

2026.10.22GitLab · Security · CVE · 학습 노트

GitLab 공식 공지와 Ruby 수정 내용을 바탕으로 정리했다

2026년 10월 22일 기준으로 CVE-2026-110264의 원인과 영향 버전을 정리했다.[1]

정규식 오버플로가 GitLab 서버의
코드 실행으로 이어질 수 있었다.

GitLab은 10월 21일 CE와 EE를 위한 긴급 보안 업데이트를 공개했다. 가장 심각한 문제는 CVE-2026-110264다. 정규식을 컴파일하는 과정에서 정수 오버플로가 발생해 특정 조건에서 인증하지 않은 공격자가 서버에서 코드를 실행할 수 있었다.[1]

CVSS 점수는 10.0이다. 네트워크를 통해 공격할 수 있고 사전 권한이나 사용자 동작이 필요 없다고 평가됐다. 다만 GitLab은 악용에 “특정 조건”이 필요하다고 밝혔다. 실제 노출 여부는 설치 환경과 해당 조건을 함께 확인해야 한다.

같은 시기 공개된 PHP 취약점과 영향 대상이 다르다. 여기서 다루는 문제는 GitLab 서버에 포함된 Ruby 정규식 처리 코드에서 발생했다.

정규식의 번호가 범위를 넘었다

GitLab은 Ruby의 정규식 엔진인 Onigmo를 사용한다. Onigmo는 정규식 안의 반복과 특정 확인 작업에 내부 번호를 붙인다. 이 번호는 부호 있는 16비트 값으로 저장되지만 번호를 세는 쪽은 더 큰 정수형을 썼다. 반복 항목이 32,767개를 넘으면 번호가 음수로 돌아설 수 있었다.[2][3]

정규식을 실제로 검사할 때 엔진은 이 번호를 반복 상태를 찾는 데 사용한다. 잘못된 음수 번호가 들어오면 메모리의 엉뚱한 위치에 쓰기가 발생할 수 있다. GitLab은 이 오류가 특정 조건에서 서버 코드 실행으로 이어질 수 있다고 밝혔다.

수정은 범위를 넘긴 패턴을 컴파일 단계에서 거부하는 방식이다. Ruby 정규식 엔진은 이런 패턴에 RegexpError를 반환한다. GitLab은 이 수정 사항을 제품에 포함된 Ruby 3.3과 3.4 그리고 4.0 계열로 옮겼다.[2]

정규식은 문서를 그릴 때도 실행된다

GitLab 보안팀의 공개 탐지 자료는 이번 취약점이 Org-mode 문서 렌더링 경로와 관련 있다고 설명한다. GitLab이 .org 파일을 화면에 표시할 때 Ruby 정규식 엔진을 사용한다.[4]

GitLab은 잠재적 시도를 찾도록 두 가지 탐지 자료도 공개했다. 하나는 Onigmo를 거치는 워커의 네이티브 충돌을 찾는다. 다른 하나는 Org-mode 렌더링 오류가 짧은 시간에 반복되는 상황을 찾는다. 둘 다 보조 신호다. 성공한 공격은 충돌을 남기지 않을 수도 있다. 로그에서 신호를 찾지 못했다고 침해가 없었다고 단정할 수는 없다.[4][5]

GitLab의 패치 공지는 구체적인 요청 예시를 공개하지 않았다. 공개된 탐지 자료는 취약점의 원인과 문서 렌더링 경로를 설명한다.

10월 12일 취약점과 원인이 다르다

10월 12일에도 정규식 처리와 관련된 CVSS 10.0 취약점이 공개됐다. CVE-2026-97229는 CI/CD 설정의 정규식 처리 경로에서 발생했다. CVE-2026-110264는 Org-mode 문서 렌더링 경로에서 발견됐다. 둘 다 Ruby의 Onigmo에 닿지만 입력 경로와 오류는 다르다.[6]

10월 12일 패치 버전으로 올린 관리자도 이번 수정 버전을 확인해야 한다. 예를 들어 19.4.2를 사용한다면 19.4.3으로 업데이트해야 한다.

영향 버전과 수정 버전

GitLab은 CE와 EE의 7.0부터 아래 수정 버전 이전까지 영향을 받는다고 안내했다.

  • 19.5는 19.5.1 이상
  • 19.4는 19.4.3 이상
  • 19.3은 19.3.6 이상
  • 19.2는 19.2.9 이상
  • 19.1은 19.1.9 이상
  • 19.0은 19.0.10 이상
  • 7.0부터 18.11 계열은 18.11.13 이상

GitLab.com은 이미 수정 버전을 사용 중이다. GitLab Dedicated도 내부 버전 19.3.5-internal0 또는 19.4.2-internal0 이상이면 조치할 필요가 없다고 밝혔다. 자체 운영 인스턴스는 배포 방식과 관계없이 수정 버전을 적용해야 한다.[1]

업데이트 일정에는 데이터베이스 마이그레이션도 고려해야 한다. 19.3.6과 19.4.3은 일반 마이그레이션을 포함한다. 단일 노드 설치는 마이그레이션이 끝날 때까지 서비스 중단이 필요하다. 다중 노드는 정해진 절차를 따르면 무중단 업데이트가 가능하다.[1]

같은 패치에 포함된 나머지 취약점

이번 릴리스는 보안 문제 12건을 수정했다. CVE-2026-110264 외에도 OmniAuth SAML과 LDAP 자동 연결 설정에서 계정 탈취로 이어질 수 있는 문제와 OAuth/OIDC 캐시를 오염시켜 로그인 흐름을 바꿀 수 있는 문제가 포함됐다. 나머지는 GraphQL 권한 범위와 멤버십 잠금 문제, 내부 자격 증명 및 비공개 프로젝트 정보 노출, 병합 승인과 AI 기능 권한 문제 등이다.[1]

GitLab의 패치 공지에는 CVE-2026-110264가 실제 공격에 사용됐는지에 대한 언급이 없다. 현재 확인된 건 취약점이 보고됐고 GitLab이 즉시 업데이트를 권고했다는 점까지다.
