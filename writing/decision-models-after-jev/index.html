Jev 이후 등장한 판정 모델 조사

공식 제품 문서와 발표를 기준으로 2026년 10월 12일에 정리했다. 직접 모델별 성능을 비교한 실험은 아니다.

새로 나온 모델들은
글을 읽고 정해진 답을 고른다.

Jev를 찾아본 뒤 비슷한 서비스가 빠르게 늘었다. Cloudflare는 Clef를 내놨고, Microsoft는 Decision-1을, OpenAI는 Decisions API를 공개했다. Upstage와 Perplexity, Fastino도 각자 판정 API를 제공한다. 내려받아 직접 돌리는 모델도 이어졌다.

이름과 출시 발표만 보면 다 같은 일을 하는 것 같지만 차이가 있다. API 가격과 호스팅 방식이 다르고, 입력할 수 있는 자료와 벤치마크도 제각각이다. CoveLetter에서 쓸 모델을 고르려면 먼저 무엇을 비교하는지 나눠 볼 필요가 있다.

문장을 만드는 대신 판정을 돌려준다

판정 모델은 상태와 질문을 받아 정해진 형식으로 답한다. 예를 들어 자소서와 경험 근거를 주고 “이 주장이 자료에 있는가”, “문항의 요구에 답했는가”, “두 수정안 중 어느 쪽이 기준에 더 맞는가”를 물을 수 있다. 답은 참·거짓 확률, 선택지, 점수처럼 프로그램이 바로 읽을 수 있는 값이다.

이런 모델은 글을 고쳐 쓰거나 이유를 길게 설명하지 않는다. 따라서 AI가 쓴 문장을 사람처럼 바꾸는 교정기나 AI 작성 탐지기와는 다르다. ‘더 자연스럽다’ 같은 기준도 직접 정의해야 한다. 그 기준에 따라 모델이 점수를 낼 수는 있지만, 점수가 글의 객관적인 품질이나 사실성을 보증하지는 않는다.

호스팅 API는 가격과 입력 범위부터 다르다

아래 요금은 2026년 10월 12일 공개 문서에서 확인했다. 대부분은 입력 토큰 100만 개 기준이다. Perplexity는 1,000회 판정 단가를 공개했다. 과금 단위가 달라 표의 숫자를 그대로 비교할 수는 없다. 이미지·영상 토큰 산정이나 계정 요금도 별도로 확인해야 한다.

토큰 단가만 보면 Clef-flash가 낮다. Perplexity는 판정 횟수 기준 요금을 공개했으므로 입력 길이가 달라질 때 비용을 같은 방식으로 비교할 수 없다. OpenAI Decisions와 Solar Decide는 토큰 단가가 더 높지만 이미지 입력과 긴 문맥을 지원한다. Upstage는 한국어 이해력을 내세운다. Solar Decide는 선택지가 26개를 넘으면 한 번의 판정으로 처리하지 못한다. Clef도 모델별 문맥 길이와 요금이 다르다.

API 모양도 전부 같지는 않다. Clef와 Solar Decide, GLiDE는 System One 형식을 따른다고 안내한다. Microsoft는 비슷하게 상태와 질문을 받지만 Azure 배포와 인증이 필요하고, OpenAI는 별도 /v1/decisions API를 쓴다. 기존 Jev 호출 코드를 그대로 쓸 수 있는지 확인하지 않고, 모델 이름만 바꾸는 방식으로 접근하면 안 된다.

공개 모델은 직접 운영하는 선택지다

Laya는 로컬에서 선택·점수·예/아니요 판단을 실행하는 엔진이다. 여러 체크포인트와 라우터를 제공하고, 프로젝트 문서는 100개가 넘는 언어를 지원한다고 설명한다. 앞선 Jev 글에서 살펴봤듯, 한국어 자소서에서 쓸 만한지는 별도 평가가 필요하다.

H2O-Lightning-4B는 이미지 입력도 받는 4B 공개 가중치 모델이다. Apache 2.0 라이선스로 공개됐고 vLLM으로 실행할 수 있다. AWS Strands 팀의 Strands Decider처럼 작은 체크포인트를 내려받아 CPU나 Apple Silicon에서 시도할 수 있는 프로젝트도 나왔다.

모델 가중치를 받을 수 있다고 해서 곧바로 관리형 서비스가 생기는 것은 아니다. 하드웨어를 준비하고 추론 서버를 운영해야 하며, 체크포인트마다 정확도와 확률 보정, 라이선스를 확인해야 한다. 대신 민감한 경험 자료를 외부 API로 보내지 않고 로컬에서 처리하는 구성을 만들 수 있다.

발표된 숫자를 한 줄로 세우기 어렵다

각 회사는 서로 다른 평가 결과를 내놓았다. Cloudflare가 인용한 TypeSafe 자체 평가 표에서는 Clef가 네 업무 유형 가운데 세 곳에서 Jev보다 높은 값을 보였다. Microsoft는 36개 벤치마크에서 Decision-1 평균 정확도 83.5%, Jev 82.3%를 보고했다. Perplexity는 1,071개 사례의 정확도 94.5%를 발표했다. H2O는 JevBench의 종합 점수에서 자사 모델이 Jev보다 높았다고 모델 카드에 적었다.

이 수치는 같은 시험에서 얻은 결과가 아니다. Microsoft와 Cloudflare의 수치는 각 회사가 구성한 평가를 포함하고, Perplexity의 94.5%도 다른 사례 묶음에서 나온 값이다. H2O가 제시한 JevBench 수치는 여러 축을 합친 종합 점수라 정답률과 같은 뜻이 아니다. 순위 하나로 제품의 우열을 정하기보다 시험 데이터, 모델 버전, 장비, 비용 계산 방식을 같이 봐야 한다.

한국어 자기소개서에 대한 공개 성능 평가는 이 자료들에서 확인하지 못했다. Upstage가 한국어 이해력을 강점으로 소개한다는 점은 시험 후보를 고르는 데 참고할 수 있지만, 한국어 자소서를 실제로 잘 판단한다는 증거와는 구분해야 한다.

CoveLetter에서는 같은 초안을 나란히 넣어 본다

첫 비교에서는 GPT 초안 A를 바탕으로 만든 두 갈래, 프롬프트 개선안 B와 Jev 점수를 반영한 수정안 C를 고정한다. Jev 외의 판정 모델에도 같은 경험 자료와 기준을 준 뒤 B와 C를 평가하게 하면, 작성에 사용한 모델이 자기 결과를 다시 고르는 순환을 줄일 수 있다.

처음에는 Jev, Clef-flash, Solar Decide 정도를 후보로 삼을 만하다. Jev는 기준점이고 Clef-flash는 입력 단가가 낮고 API 호환을 내세우며, Solar Decide는 한국어 이해력과 긴 문맥을 강조한다. 같은 자료와 질문을 넣고, 두 수정안의 순서를 바꾸어 다시 물어본다. 모델의 선택과 확률뿐 아니라 내가 선호하는 문장, 근거와 맞지 않는 주장, 불필요한 수정도 따로 기록한다.

수정안 판정을 한 번 해보는 것은 절차를 익히는 데 도움이 된다. 그러나 자소서 한 편의 결과로 모델을 평가했다고 말할 수는 없다. 글자 수와 반복은 코드로 확인하고, 사실은 경험 원문과 대조한다. 애매한 판정은 보류하고 최종 선택은 사람이 한다.

Jev 이후 선택지는 많아졌다. 지금 비교할 것은 가장 높은 점수를 내세운 모델이 아니다. 같은 한국어 자료를 읽혔을 때 근거를 놓치지 않는지, 내가 불필요한 수정을 받아들이지 않게 하는지다.
