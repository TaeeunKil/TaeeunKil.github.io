kafrust

C 클라이언트 의존성 없이 Kafka와 통신하는 Rust 라이브러리

역할
라이브러리 개발과 검증
기술
Rust / Tokio / Kafka

만든 것

Kafka 프로토콜을 Rust에서 직접 다루는 클라이언트를 개발했습니다. 기본 빌드는 librdkafka와 C 툴체인 없이 사용할 수 있도록 구성했습니다.

  • 메시지를 보내고 읽는 API를 구현했습니다. 배치 전송과 버퍼링부터 멱등 프로듀서와 트랜잭션까지 확장했습니다.
  • 컨슈머 그룹의 멤버십과 하트비트 및 오프셋 커밋을 다뤘습니다. 기존 그룹 방식과 KIP-848 방식을 지원하는 경로를 만들었습니다.
  • 토픽과 그룹을 관리하는 Admin API를 추가했습니다. TLS와 SASL 인증 및 압축 기능도 구현했습니다.
  • 응답과 디코딩 크기에 제한을 두고 처리 중인 요청과 버퍼 상태를 관찰할 수 있게 했습니다.
  • 브로커 버전과 실행 환경별 검증 기록을 남겼습니다. Windows와 macOS 빌드 검사도 CI에 추가했습니다.

장애 뒤에 다시 연결됐다는 것만으로는 충분하지 않았습니다

문제
브로커나 그룹 구성원이 중간에 내려가면 재연결에 성공해도 메시지 유실과 중복 여부는 따로 확인해야 합니다. 응답이 끊긴 요청은 처리됐는지 알 수 없는 경우도 있습니다.
접근
보낸 레코드와 읽은 레코드를 대조하고 마지막에 남은 요청과 버퍼도 확인하도록 검증을 구성했습니다. 결과를 알 수 없는 요청은 별도 수치로 남겼습니다.
검증
공개 검증 기록에는 그룹 이탈과 재참여 조합 네 가지를 각각 100회 반복한 결과가 있습니다. 브로커 세 대의 리더와 코디네이터를 재시작하는 시나리오도 평문과 SASL/TLS 환경에서 확인했습니다.
결과
해당 복구 검증에서는 레코드 유실과 중복 없이 대조를 마쳤고 마지막 클라이언트 지표도 비웠습니다. 보안 연결 실행에서 남은 결과 미확정 요청은 그대로 기록했습니다.

배포와 현재 범위

저장소 문서 기준으로 crates.io 0.4.0 패키지의 외부 프로젝트 설치 검증을 마쳤습니다. 6시간 보안 연결과 12시간 평문 연결 검증 결과도 남겼습니다. 아직 1.0 이전 버전이며 장시간 성능 기준과 전체 장애 조합 검증은 별도 과제로 진행 중입니다.

문제

Mattermost AI

사용자가 확인하고 적용하는 AI 제안

역할
협업 도구 개발
기술
TypeScript / Go / React

맡은 일

사내에서 쓰는 Mattermost에 문서 화면을 추가하고 AI가 제안한 변경을 사용자가 확인할 수 있도록 만들었습니다. CI/CD 설정도 맡았습니다.

  • 기존 카드 편집기를 전체 화면 문서 뷰로 확장했습니다. 문서 안에 넣은 카드의 순서 변경과 실행 취소를 처리했습니다.
  • 팀에 들어오거나 나가면 보드 접근 권한도 따라 바뀌도록 고쳤습니다. 기존 관리자의 권한은 유지했습니다.
  • 제안 형식 검사부터 변경 적용 API와 결과 표시까지 수정했습니다. 이전 제안의 처리 상태도 다음 대화에 전달했습니다.

잘못된 제안 반복과 제목 없는 카드 식별

문제
AI가 잘못된 형식을 반복해서 만들었고 제목만으로는 변경할 카드를 정확히 찾기 어려웠습니다.
판단
모델에 보여주는 제안 규약과 실행 검증을 맞추고 조회 결과의 고유 ID를 변경 요청까지 전달해야 했습니다.
조치
Proposal.safeParse로 실행 단계에서 검증하고 모든 오류를 한 번에 반환했습니다. 검증 실패 2회 시 종료하며 최대 실행 단계를 16에서 8로 제한했습니다. cardId를 우선 사용하고 이전 제안이 적용됐는지 실패했는지를 대화에 포함했습니다.
확인
제목 없는 카드를 한 번에 바꾸는 경우와 잘못된 제안을 다시 만드는 경우를 테스트했습니다. 당시 AI 테스트 41개와 Go 검사 및 웹 빌드가 통과했습니다.
