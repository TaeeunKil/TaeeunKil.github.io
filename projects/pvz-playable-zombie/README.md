# REA로 만드는 PvZ 플레이어 좀비 모드

작성일: 2026-10-14

상태: 계획 수립. REA 설치, 게임 바이너리 분석, 모드 구현은 아직 시작하지 않았다.

고전 PC판 Plants vs. Zombies의 기존 좀비 한 마리를 플레이어가 직접 조종하는 작은 프로젝트다. REA로 실행 파일의 객체 구조와 이동 처리 경로를 분석하고, 실행 중 검증한 결과를 모드 코드에 반영한다. 최종적으로는 식물의 탄환을 피하고 식물을 먹으며 집까지 도달하는 플레이를 목표로 한다.

블로그 게시물이 아닌 프로젝트 계획이다. 현재는 이 저장소에서 계획만 관리하며, 구현을 시작할 때 독립 저장소로 옮길지 결정한다. 웹사이트의 글 목록이나 포트폴리오에 자동으로 등록하지 않는다.

## 첫 번째 완료 기준

**일반 좀비 한 마리의 자동 보행만 중지하고 A/D로 가로 이동한다.**

- 조작 대상이 명확히 식별된다.
- 선택하지 않은 좀비는 원래대로 움직인다.
- 선택한 좀비도 기존 탄환에 피격된다.
- 조작 해제 시 살아 있는 대상의 정상 동작이 복원된다.
- 대상 사망, 스테이지 종료, 재시작 시 오래된 객체를 접근하지 않는다.
- 같은 게임 판본에서 재실행해도 주소 탐색과 조작을 재현할 수 있다.

첫 버전에는 자유로운 줄 이동, 수동 공격, 사용자 정의 승패, 새 그래픽, 두 게임 연결을 포함하지 않는다. 전체 게임을 디컴파일하거나 다시 구현하는 작업도 범위 밖이다.

## 도구와 역할

| 구성 | 역할 |
| --- | --- |
| 코딩 에이전트와 REA | 실행 파일에서 함수, 명령어, 참조 관계와 필드 후보 조사 |
| Ghidra | REA가 사용하는 네이티브 정적 분석 백엔드 |
| 실행 중 디버거 | 실제 객체, 좌표 변화, 호출 시점과 실행 스레드 검증 |
| 별도 모드 코드 | 키 입력, 대상 선택, 필요한 후킹 또는 패치, 해제 처리 |

REA는 완성된 모드를 자동으로 내보내는 도구로 가정하지 않는다. Windows Ghidra 연동은 공식 안내상 실험적인 읽기 전용 분석 지원이다. 모드 구현 방식은 실행 중 검증 이후 결정한다.

## 단계별 계획

| 단계 | 작업 | 산출물과 완료 조건 |
| --- | --- | --- |
| 0. 대상 확정 | 보유한 게임의 판본, 실행 파일, 이용 조건 확인 | 파일 버전·아키텍처·SHA-256 기록. 해당 판본으로 분석 가능 여부 판단 |
| 1. 환경 준비 | Node.js, JDK, Ghidra, REA 연결 | provider 진단 통과, 실제 바이너리 함수 조회 성공 |
| 2. 이동 분석 | 좀비 생성·보관·순회·좌표 갱신 경로 추적 | 근거 주소와 함께 객체 및 이동 함수 후보 기록 |
| 3. 실행 중 검증 | 걷기·공격 중 정지·피격·사망 관찰 | 선택한 객체의 좌표와 상태를 화면 및 명령어 실행과 대조 |
| 4. 조작 시제품 | 대상 한 마리의 보행 처리와 A/D 입력 연결 | 첫 번째 완료 기준 충족, 짧은 시연 영상 |
| 5. 플레이 확장 | W/S 줄 이동, 식물 먹기, 도착 판정 | 각 기능을 별도로 검증하고 한 판을 끝낼 수 있는 시연 |

일정은 대상 판본과 도구 진단 후 정한다. 첫 분석 세션의 목표는 전체 모드 완성이 아니라 **이동 함수 후보 하나와 검증 절차 확보**다.

## 구현 방향

실행 파일에서 찾은 함수와 필드로 실행 중 상태를 해석한 뒤, 선택한 좀비에만 사용자 입력을 반영한다. 공유 이동 함수 전체를 무조건 비활성화하지 않는다.

- 실행 파일 주소, 모듈 상대 주소, 실행 중 객체 포인터를 구분한다.
- 객체 포인터를 영구 식별자로 가정하지 않는다. 사망과 재생성 시 수명 및 재사용을 확인한다.
- 초기 구현은 검증한 바이너리 해시만 지원한다. 판본이 다르면 적용하지 않는다.
- 입력 처리는 게임 포커스와 조작 모드 상태를 확인한다.
- 후킹이 필요하면 호출 규약, 레지스터 보존, 실행 스레드, 원본 코드 복원을 검증한다.
- C++ 기반 모드와 DLL 후킹을 후보로 두되, 분석 전에 기술을 확정하지 않는다.

단순 좌표 덮어쓰기는 원래 이동과 충돌할 수 있다. 실제 이동 경로를 확인한 후 적용 지점을 선택한다. 줄 이동은 화면의 Y 좌표만 바꾸는 것으로 끝내지 않고 논리적 줄 정보, 탄환 충돌, 식물 탐색도 확인한다.

## 검증 시나리오

| 상황 | 확인할 결과 |
| --- | --- |
| 일반 좀비 두 마리 이상 | 선택 대상만 입력으로 이동 |
| 입력 없음 | 대상 자동 보행 중지, 다른 좀비 정상 진행 |
| A/D 입력 및 키 해제 | 의도한 방향으로 이동하고 키 해제 시 정지 |
| 완두콩 피격 | 원래 피격 및 체력 감소 처리 유지 |
| 식물과 접촉 | 기존 공격 상태와 수동 이동 간 충돌 기록 |
| 조작 해제 | 대상의 정상 보행 복원 |
| 대상 사망 | 조작 중단, 해제된 객체 접근 없음 |
| 메뉴 복귀 및 스테이지 재시작 | 대상 참조 초기화, 새 대상 재선택 |
| 게임 종료 및 모드 종료 | 종료 순서에 관계없이 충돌 없이 정리 |
| 지원하지 않는 바이너리 | 패치나 후킹 적용 거부 |

## 후속 기능

1. W/S로 줄 이동: 시각적 위치와 공격·피격 대상 줄이 함께 바뀌는지 검증한다.
2. 식물 먹기: 먼저 기존 접촉 공격을 유지하고, 수동 공격 전환은 별도 기능으로 검토한다.
3. 도착 판정: 원래 게임 오버 처리와 분리해 플레이어 승리를 표시한다.
4. 한 판 구성: 준비된 식물 배치에서 출발해 도착까지 플레이하고 재도전할 수 있게 한다.

## 기록 및 공개 범위

분석 로그에는 REA가 제안한 가설, 실행 중 확인한 사실, 외부 자료에서 가져온 정보를 구분한다. [분석 실행 안내](ANALYSIS.md)의 기록 양식을 사용한다.

게임 실행 파일, 에셋, 세이브, 메모리 덤프는 이 저장소에 넣지 않는다. 공개용 코드와 영상의 범위는 해당 판본의 EULA와 모드 정책을 확인한 뒤 결정한다. 기존 역공학 프로젝트의 존재를 권리자의 허락으로 해석하지 않는다. 원본 코드나 에셋을 외부 AI 서비스에 전달하는 범위도 확인한다.

기존 주소표는 첫 분석의 정답으로 주입하지 않는다. 막힌 부분의 대조 자료로 사용하면 출처와 참고 시점을 남긴다. 특정 버전의 알려진 주소를 다른 판본에 그대로 적용하지 않는다.
